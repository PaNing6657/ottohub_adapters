# OTTOhub 社交能力插件

AstrBot 插件,让机器人获得 OTTOhub 平台的社交操作能力。

## 功能

| 能力 | 命令 | 说明 |
|------|------|------|
| 查看用户详情 | `/用户详情 <uid>` | 查询用户资料(简介/作品数/粉丝数等) |
| 发布动态 | `/发动态 <标题>|<内容>` | 以配置账号身份发布动态,末尾自动署名 |
| 查看动态详情 | `/动态详情 <bid>` | 通过动态 ID(bid)查看完整内容 |
| 搜索动态 | `/搜索动态 <关键词> [数量]` | 支持按最新/浏览/点赞/收藏排序 |
| 用户动态 | `/用户动态 <uid> [数量]` | 查看指定用户最近发布的动态列表(默认 10 条) |
| 评论动态 | `/评论 <bid> <内容>` | 评论动态,开头自动加转达前缀 |
| 回复评论 | `/回复 <bid> <bcid> <内容>` | 回复动态下的某条评论 |
| 关注用户 | `/关注 <uid>` | 关注指定用户 |
| 取关用户 | `/取关 <uid>` | 取消关注 |
| 主动发送私信 | `/发消息 <uid> <内容>` | 主动给任意用户发送私信(超长自动分片) |
| 匿问我答 | `/q <uid> <问题>` | 匿名提问(纯命令,不经 LLM),对方用 `/a` 回答 |
| 匿问回答 | `/a <编号> <回答>` | 被问者回答匿名提问,自动转达给提问者 |
| 匿问状态 | `/匿问状态 [编号]` | 查询我发起的/我收到的匿问记录与回答情况 |

辅助命令:

- `/关注状态 <uid>` — 查询是否已关注
- `/会话列表` — 最近联系人(便于查找 uid)
- `/ottohub帮助` — 查看全部命令

## 自动署名与转达前缀

- **发动态**:正文结尾自动追加 `—— 由「发送者昵称」让我代发`,说明动态是谁让机器人发布的;正文超长时截断正文以保留署名。
- **评论/回复**:内容开头自动添加 `发送者昵称让我转达:`,表明评论由谁转达;总长超过 459 字上限时截断正文以保留前缀。
- **私信**:内容开头自动添加 `帮{发送者昵称}转达:`,超长分片时前缀保留在第一片。

## 匿问我答(纯命令,不经 LLM)

提供「匿名提问 → 对方回复 → 转达回答」的完整闭环,**全程命令驱动,不经过 LLM**(提问前的 LLM 审核除外):

- `/q <uid> <问题>` — 匿名提问(LLM 审核通过后发送)
- `/q on` / `/q off` — 开启/关闭当前用户接收匿问
- `/a <编号> <回答>` — 回答匿问(被问者使用)
- `/匿问状态 [编号]` — 查询我发起的/我收到的匿问记录

工作流程:

1. 提问者执行 `/q 123 你最近在忙什么?`(仅管理员可发起,属写操作)。
2. **LLM 审核**:插件调用当前对话模型审核问题——仅允许**询问类**内容,拒绝非询问语句与色情/暴力/违法/赌博/侮辱/涉政等敏感问题;审核不通过则不发送。若未配置 LLM 或审核服务异常,放行(不阻塞正常提问)。
3. **接收开关检查**:若对方执行过 `/q off`,则提示"对方已关闭匿问接收",停止提问。
4. 审核通过后,插件分配**短问题编号**(全局递增的数字:1、2、3…,方便记忆与输入),以**匿名私信**发送给被问者——对方只看到问题与编号,看不到提问者身份。
5. 被问者回复私信执行 `/a 1 最近在写代码`,插件校验身份(仅被问者可答)后把回答转达给提问者,格式 `{回答者昵称}回答了你的问题 #1:回答内容`。
6. 问答记录本地持久化存储(插件 `data/ottohub_qa.json`),重启不丢失。

细节:

- **LLM 审核**:审核通过 `context.get_using_provider().text_chat()` 调用当前对话模型,要求模型仅输出 `{"allowed": true/false, "reason": "..."}`;拦截时向提问者展示拒绝原因,问题不会发送。
- **接收开关**:按发送者 UID 记录(`data/ottohub_qa.json` 的 `receive_switch` 字段),默认接收;关闭后他人提问会在审核前被拦截。
- **匿名性**:提问者身份只保存在本地记录中,发送给被问者的私信不含任何提问者信息;转达回答时展示的是**回答者**昵称。
- **短编号**:问题编号为全局递增纯数字(`/q` 后提示),被问者照抄即可回答,无需记忆长 ID。
- **回答权限**:仅被问者本人(记录中的目标 UID)可回答对应提问;已回答的问题不可重复回答。
- **状态查询**:`/匿问状态 [编号]` 可查"我发起的"或"我收到的"匿问记录(问题、待回答/已回答状态、回答内容),查询遵循权限隔离(提问者按会话、被问者按 UID),结果**永不显示提问者身份**。

> 注意:匿问的提问与回答均为纯命令,不经 LLM;但 **OTTOhub 平台私信(含匿问私信)会进入 AstrBot LLM 对话**,二者互不影响。

## 自然语言对话(LLM 自动调用)

除了命令方式,插件还将全部能力注册为 **LLM 工具**,支持自然语言对话。你不需要记命令,直接对 bot 说:

```
帮我看看用户 123 的资料
发一条动态:标题"今日分享",内容"今天天气真好~"
查一下动态 1001 的内容
搜索一下"赛博朋克"相关的动态
看看用户 123 最近发了哪些动态
在动态 1001 下发条评论"写得太好了"
关注一下用户 456
给用户 789 发消息"你好呀"
```

> 匿问我答为**纯命令**能力(`/q`、`/a`、`/匿问状态`),不经 LLM,不在上述自然语言范围内。

LLM 会自动选择合适的工具、提取参数并调用,再把结果整理成自然语言回复。发动态、评论的自动署名/转达前缀同样生效。

工具执行的结果(成功、失败、审核状态等)会作为返回值交给 LLM,由 LLM 用自己的语言组织后回复用户,不会直接输出插件原始文案。

**启用前提**:

1. 使用的模型必须支持函数调用(function calling)
2. 在 AstrBot WebUI 的「工具」管理中,启用本插件提供的 `ottohub_*` 工具。
3. 工具调用同样受「管理员用户ID」权限约束(发动态/关注/取关/发消息为写操作)。

> 命令方式与工具方式可同时使用,互不影响。

## 安装

将 `astrbot_plugin_ottohub_actions` 目录放入 AstrBot 插件目录,在面板中启用插件并填写配置。

## 配置

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| API地址 | OTTOhub API 基础地址 | `https://api.ottohub.cn` |
| Token | 登录 Token;留空则用账号密码自动登录 | 空 |
| 用户ID | OTTOhub 账号(邮箱/用户名),Token 留空时使用 | 空 |
| 密码 | OTTOhub 登录密码,Token 留空时使用 | 空 |
| 管理员用户ID | 允许执行写操作的用户 ID 列表;留空表示所有用户可用 | 空 |

认证说明:

- **方式一(推荐)**:直接填写 Token,插件无需登录流程。
- **方式二**:填写 用户ID + 密码,插件自动登录;Token 失效时会自动重新登录并重试请求。

## 权限

- **读操作**(用户详情 / 动态详情 / 搜索 / 会话列表 / 关注状态):所有用户可用。
- **写操作**(发动态 / 评论 / 回复 / 关注 / 取关 / 发消息 / 匿问`/q`):仅「管理员用户ID」列表中的用户可用;列表留空时所有用户可用。

## 命令示例

```
/用户详情 123
/发动态 今日分享|今天天气真好~
/发动态 今天天气真好~          (不写标题,自动取前30字作标题)
/动态详情 1001
/搜索动态 赛博朋克 5 点赞
/用户动态 123 10
/评论 1001 写得太好了
/回复 1001 55 同意楼上
/关注 123
/取关 123
/关注状态 123
/发消息 123 你好呀
/q 123 你最近在忙什么?
/q off               (关闭接收匿问;/q on 恢复)
/a 1 最近在写代码     (被问者回复匿问,编号来自收到的私信)
/匿问状态           (也可带编号:/匿问状态 1)
/会话列表
/ottohub帮助
```

## 依赖

- `astrbot` >= 4.1.0
- `aiohttp`(AstrBot 内置依赖)

> 兼容性说明:不同 AstrBot 版本对事件过滤器的 API 命名存在差异(`EventMessageType` 可能在 `astrbot.api.event` 顶层或 `astrbot.api.event.filter` 子模块;事件过滤器装饰器可能叫 `event_message_type` 或 `event_type`)。插件已对两处均做自动兼容,无需手动处理。
